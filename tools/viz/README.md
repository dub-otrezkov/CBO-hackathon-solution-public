# Визуализатор работы решения на одной записи

`viz.py` прогоняет ядро решения из `src/tram_odometry` на одной записи офлайн, так же как это делает нода: сообщения идут в порядке записи, GNSS доступен только в первые 5 с после первого сообщения GNSS. По ходу прогона скрипт снимает внутренние величины фильтра и пишет одну HTML-страницу с графиками. Код в `src/` скрипт не меняет, он только читает состояние ядра. С ключом `--check` ядро прогоняется ещё раз без съёма величин, и все выходы (метка, x, y, z, скорость) сравниваются бит в бит.

## Что нужно

- Окружение ROS 2 Humble и собранные пакеты решения (`colcon build`, затем `source install/setup.bash`). Записи скрипт читает средствами ROS 2 (`rclpy`), numpy входит в `ros-base`. Если установлен pip-пакет `rosbags`, скрипт возьмёт его, но он не обязателен.
- Браузер с доступом в интернет: страница загружает plotly.js 2.35.3 с `cdnjs.cloudflare.com`. Это единственный внешний ресурс, данные лежат внутри страницы.

## Запуск

```sh
cd <папка решения>
source /opt/ros/humble/setup.bash && source install/setup.bash

# эталон из топика /localization/kinematic_state проверочной записи организаторов
python3 tools/viz/org_ref.py <каталог с записями>/30618_88aea4d9 viz_ref

# страница
python3 tools/viz/viz.py 30618_88aea4d9 --data <каталог с записями> --ref viz_ref --out 30618_88aea4d9.html --check
```

Первый аргумент `viz.py` — имя папки записи, `--data` — каталог, в котором эта папка лежит. Если в записи нет топика `/localization/kinematic_state`, запускайте `viz.py` без `--ref`: страница построится, но без графиков ошибки. В контейнере с 2 ядрами страница проверочной записи (21.8 мин) строится за 17 с и весит 4.5 МБ. Скрипт печатает сводку в JSON, с `--check` код возврата 2 означает расхождение выходов.

Страницу открывают в браузере двойным щелчком. Если браузер не открывает локальный файл, подойдёт `python3 -m http.server 8000` в папке со страницей и адрес `http://localhost:8000/`.

Готовая страница проверочной записи лежит в `examples/30618_88aea4d9.html`. Она собрана этими командами на коде из этой папки.

## Что на странице

Общий ползунок времени двигает метку на всех графиках, наведение курсора по времени тоже общее.

1. Карта: оба маршрута, эталон, наш трек с цветом по модулю ошибки, фиксы GNSS первых 5 с, стартовая точка, платформы, привязки по отпечатку пути и по стоянке. Щелчок по легенде включает дополнительные слои: сырые фиксы GNSS за всю запись и треки, которые дали бы по отдельности колёса, модель тяги и доплеровская скорость GNSS. Рядом крупный план вокруг текущей точки.
2. Сведение источников: ошибка вдоль пути у каждого источника отдельно и у фильтра, полоса ±√P_ss фильтра, привязки с их σ, вес тележек и коэффициент усиления K каждого обновления фильтра.
3. Скорости тележек (км/ч ÷ 3.6), наша скорость и эталон, м/с; эпизоды проскальзывания и юза.
4. Позиция контроллера, от −15 до +15.
5. Вес каждой тележки в фильтре, от 0 до 1.
6. Ошибка вдоль и поперёк пути, м, моменты привязок и поправка пути при каждой привязке.
7. Масштаб колёс w и √P_ss фильтра, м.
8. Профиль отпечатка пути r = (v_перед − v_зад)/v вдоль пути: карта и эта запись, принятые привязки, разбор выбранной привязки с корреляцией.

Внизу страницы есть раздел «Определения»: как выход сопоставляется с эталоном, как прорежены ряды, что не показано.

Источники в разделе 2 считаются каждый сам по себе, без фильтра, от момента выравнивания по GNSS. «Только колёса» интегрирует среднее двух тележек без обработки проскальзывания и масштаба. «Только модель тяги» интегрирует ускорение модели по контроллеру с c = 1 и b = 0, без колёс. «Только доплер» интегрирует доплеровскую скорость GNSS; её решение видит только первые 5 с, здесь она нужна для сравнения. «GNSS на маршруте» проецирует фикс антенны master на маршрут и показывает, какую ошибку даёт сама схема «точка маршрута + 9.873 м» при точном пути.
